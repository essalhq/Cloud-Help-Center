Essal Access distingue l’administration de l’organisation du libre-service employé. Attribuez un rôle selon les responsabilités réelles, puis vérifiez les pages et actions accessibles.

## Les quatre rôles

| Rôle | Accès | Limites importantes |
| --- | --- | --- |
| Admin | Tableau de bord et administration de l’organisation | Le concepteur de badges exige ce rôle. Vérifiez l’organisation avant de changer les paramètres communs. |
| Manager | Tableau de bord, employés, impression, visiteurs, scans, pass, utilisateurs, paramètres, éditeurs de page publique et de carte, audit | Voir une page ne donne pas toutes les actions administratives. Le concepteur de badges n’est pas disponible. |
| Security | Tableau de bord, liste des employés, visiteurs, scans et audit | Accès opérationnel ; la gestion des employés et de l’organisation est limitée. |
| Employee | Portail employé | Une fiche employé ne donne pas automatiquement accès au tableau de bord administrateur. |

## Admin

Réservez Admin aux responsables de la configuration et des actions privilégiées. Le concepteur de badges exige Admin dans l’application actuelle. Vérifiez la portée d’une modification avant d’enregistrer le modèle partagé.

## Manager

Les gestionnaires assurent les opérations courantes. Plusieurs pages sont accessibles, mais leur visibilité ne garantit pas le droit d’inviter, suspendre, supprimer ou modifier chaque élément. Utilisez les commandes proposées et demandez à un Admin si une action manque.

## Security

Les équipes de sécurité utilisent le tableau de bord, la recherche d’employés, les visiteurs et les journaux pour les contrôles. Partagez uniquement les informations nécessaires à la tâche.

## Employee

Les employés utilisent le lien du portail fourni pour consulter leur badge et les actions de profil ou de carte autorisées. Si aucun badge n’apparaît, demandez à l’administrateur de vérifier l’association entre le compte et la fiche.

## Attribuer et vérifier l’accès

1. Confirmez l’organisation et la personne.
2. Ouvrez les commandes de gestion des utilisateurs avec un compte autorisé.
3. Choisissez le rôle minimal utile et confirmez.
4. Demandez à la personne de se connecter avec son propre compte et vérifiez les droits attendus.

Si une page manque, contrôlez le rôle avant de signaler une panne. Ne partagez pas un compte Admin et ne supposez pas qu’un rôle d’une autre application s’applique ici.


## Besoin d’aide ?

Si une action manque, vérifiez [votre rôle](/fr/access/getting-started/understanding-user-roles) et l’organisation active. Consultez [le dépannage](/fr/troubleshooting/common-problems) ou [contactez l’assistance](/fr/introduction/contact) avec le message exact.
